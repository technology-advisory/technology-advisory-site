Delegaciones peligrosas, ACL y rutas de ataque en Active Directory

Análisis de permisos, AdminSDHolder, GPO, delegación Kerberos, trusts y relaciones explotables para priorizar la remediación por impacto real.

Miguel Ángel Carriazo18 Junio 2026Active DirectoryLectura avanzada (18–24 min)
01 // ACL y rutas de ataque

Modelo de amenaza

El atacante no necesita comprometer todos los controles; necesita una ruta válida desde una identidad o equipo de baja confianza hasta un principal con capacidad de modificar el dominio. Active Directory acumula relaciones transitivas, permisos heredados, secretos reutilizados y mecanismos de compatibilidad. El análisis debe estudiar caminos completos de ataque, no únicamente configuraciones aisladas.

En este ámbito, writeDACL, GenericAll, ForceChangePassword y control de GPO crean rutas de escalado. AdminSDHolder y SDProp pueden restaurar permisos privilegiados inesperados. Esta combinación obliga a analizar personas, procesos y tecnología como un único sistema. Una decisión correcta sobre el papel puede fallar si el equipo no dispone de inventario, autoridad o tiempo para aplicarla de forma consistente.

El análisis práctico debe responder al menos a cuatro preguntas: qué activo o proceso se protege, quién puede modificarlo, qué señales permiten detectar una desviación y cómo se recupera el estado confiable. La delegación unconstrained, constrained y resource-based cambia el alcance de suplantación. La priorización debe considerar camino completo, facilidad y criticidad del objetivo. Las respuestas deben quedar en arquitectura, runbooks, estándares o matrices de control, según corresponda, y no únicamente en conocimiento informal de los administradores.

La evidencia esperada incluye una línea base, resultados de consultas o pruebas, registro de decisiones, incidencias conocidas y criterios de aceptación. Conviene separar evidencia de diseño —lo que se pretende— de evidencia operativa —lo que realmente sucede—. Cuando ambas no coinciden, la diferencia debe tratarse como hallazgo o excepción, con responsable y fecha.

Para evitar una implantación puramente documental, cada control debe asignarse a un mecanismo verificable y a una frecuencia. Las revisiones deben seleccionar muestras de alto riesgo, incluir cambios recientes y comprobar que las acciones correctivas no introdujeron nuevas dependencias. La calidad se mide por reducción de exposición y capacidad de recuperar confianza, no por el número de documentos producidos.

Controles preventivos

Los controles preventivos deben reducir privilegios, limitar dónde puede autenticarse cada identidad, eliminar protocolos y cifrados heredados, proteger secretos y separar el plano administrativo. El diseño debe favorecer credenciales administradas, autenticación resistente al phishing, estaciones privilegiadas y permisos delegados mediante grupos con alcance claro.

09 // conclusión

Conclusión

Delegaciones peligrosas, ACL y rutas de ataque en Active Directory no debe abordarse como una actividad aislada. Requiere decisiones explícitas, controles técnicos, disciplina operativa y evidencia suficiente para demostrar que el riesgo permanece dentro de los límites aceptados.

La prioridad es crear una cadena completa desde el requisito hasta la recuperación: inventario fiable, arquitectura comprensible, privilegios limitados, operación observable y pruebas repetibles. Cuando esa cadena existe, Active Directory deja de depender de conocimiento informal y se convierte en un servicio gobernado, defendible y recuperable.
