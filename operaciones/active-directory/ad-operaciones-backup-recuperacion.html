Operaciones · Active Directory

Backup, recuperación y disaster recovery de Active Directory

Respaldo de estado del sistema, restauración autoritativa y no autoritativa, forest recovery, aislamiento de copias y pruebas completas de recuperación.

Miguel Ángel Carriazo01 Agosto 2026Active DirectoryLectura avanzada (18–24 min)
01 // Backup y recuperación

Active Directory como servicio crítico

Operar Active Directory significa mantener una cadena completa de capacidades: DNS, tiempo, replicación, SYSVOL, autenticación, autorización, certificados y administración. Un controlador encendido no equivale a un servicio sano. La operación debe observar experiencia, convergencia, capacidad y dependencia, y debe distinguir entre síntomas locales y degradación sistémica.

En este ámbito, system State es necesario, pero la estrategia debe incluir forest recovery y datos auxiliares. Las copias deben estar aisladas de las credenciales y del plano de administración del dominio. Esta combinación obliga a analizar personas, procesos y tecnología como un único sistema. Una decisión correcta sobre el papel puede fallar si el equipo no dispone de inventario, autoridad o tiempo para aplicarla de forma consistente.

El análisis práctico debe responder al menos a cuatro preguntas: qué activo o proceso se protege, quién puede modificarlo, qué señales permiten detectar una desviación y cómo se recupera el estado confiable. La restauración autoritativa se usa con criterio para evitar inconsistencias. Las pruebas deben medir tiempo, orden, dependencias y capacidad del equipo. Las respuestas deben quedar en arquitectura, runbooks, estándares o matrices de control, según corresponda, y no únicamente en conocimiento informal de los administradores.

La evidencia esperada incluye una línea base, resultados de consultas o pruebas, registro de decisiones, incidencias conocidas y criterios de aceptación. Conviene separar evidencia de diseño —lo que se pretende— de evidencia operativa —lo que realmente sucede—. Cuando ambas no coinciden, la diferencia debe tratarse como hallazgo o excepción, con responsable y fecha.

Para evitar una implantación puramente documental, cada control debe asignarse a un mecanismo verificable y a una frecuencia. Las revisiones deben seleccionar muestras de alto riesgo, incluir cambios recientes y comprobar que las acciones correctivas no introdujeron nuevas dependencias. La calidad se mide por reducción de exposición y capacidad de recuperar confianza, no por el número de documentos producidos.

02 // Backup y recuperación

Rutinas operativas

Las rutinas diarias y semanales deben ser breves, automatizadas y orientadas a excepciones. Se revisan errores de replicación, salud de DNS, estado de SYSVOL, capacidad, eventos críticos, cambios privilegiados y resultados de backup. Las comprobaciones manuales quedan reservadas para investigar desviaciones, no para sustituir una monitorización deficiente.
